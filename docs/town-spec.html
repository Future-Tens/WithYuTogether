小鎮 /小鎮

一個在 Discord 裡慢慢經營的小遊戲：每天簽到、種田、下礦坑，把收成賣掉換風幣，再去朋友的農場幫忙澆水除蟲。所有操作都在同一則訊息上用按鈕完成。

第一部分 · 給玩家

怎麼玩

一天的節奏

每個伺服器各自一個小鎮，錢包和進度只在該伺服器有效。新玩家開局有 2 塊田、100 風幣。輸入 /小鎮 打開自己的農場，之後全部用按鈕操作；輸入 /小鎮 @某人 可以拜訪別人的農場。

早上簽到、收成、補種領每日風幣，收昨晚種的長時作物，換種 1–2 小時的短作物。
中午收短作物、出發挖礦賣掉收成，選一趟 4 小時的礦坑行程。
傍晚逛朋友的農場幫忙澆水、除蟲、按讚，順便賺點小費。
睡前種 8 小時作物過夜作物有足夠的寬限期，隔天早上收剛好。

設計目標是一天回來 3 次以上會玩得很順，但一天只來一次也不會被重罰。

每日簽到

每天台灣時間 00:00 換日，簽到領 50 風幣。簽到看的是累計天數，中斷不會歸零。

農田與作物

買種子、種下、等它長大、收成、賣掉。短作物時薪高但要常回來，長作物一次賺得多、適合過夜。

成熟後別放太久

寬限期 = 該作物的生長時間（最少 2 小時）。例如南瓜成熟後 8 小時內收是新鮮的，再 8 小時內收是過熟。

🟡 過熟再一個寬限期，售價 50%
🥀 枯萎只能清除，無收成

🐛 蟲害

每株作物有 30% 機率長蟲，而且只會在生長期間的前 80% 出現，收成前一定有時間處理。自己或路過的朋友都可以除蟲；蟲沒除到收成時，售價 −30% 且稀有變異失效。

✨ 稀有作物

每株作物成熟時都有機會變異。變異在成熟那一刻揭曉，會直接顯示在你的公開農場畫面上。

互動原則

  • 每個操作都 編輯同一則訊息，子畫面一律有「⬅ 返回」。
  • 錯誤、背包明細、賣出確認、訪客操作的回饋都用 ephemeral。
  • 按鈕用 discord.ui.DynamicItem，custom_id 格式 town:<action>:<owner_id>[:<arg>]，重啟後仍可用；guild_id 取自 interaction。
  • 每次點擊都從 DB 重讀狀態再重繪，不信任訊息上的舊資料。
  • 擁有者按鈕檢查 interaction.user.id == owner_id；訪客按鈕反過來，擁有者自己按澆水或按讚會被拒。除蟲兩邊都能按。
  • 倒數用 <t:ready_at:R>，Discord 會自動更新顯示。

規則實作

種下時就決定隨機結果

種植時一次擲完：mutation、mutation_alt（澆水時取兩者較好的）、pest_at（依 pest_chance 擲骰，中了就落在生長期間前 80% 內的隨機時間點，否則 NULL）。成熟前不顯示變異。這樣重新整理畫面無法刷結果。

礦坑在收取時才擲骰

收取是一次性動作，先用條件式 DELETE 搶到這趟行程，成功才擲骰發獎勵。

作物狀態判斷（純函式，放 town_service）

grace = max(2h, grow_time)
now < ready_at                      → 生長中
now < ready_at + grace              → 新鮮
now < ready_at + 2 × grace          → 過熟（售價 × 0.5）
else                                → 枯萎
pest_at = planted_at + random(0, pest_window × grow_time)   （pest_window = 0.8）
有蟲 = pest_at IS NOT NULL AND pest_at <= now AND NOT pest_cleared
收成時有蟲 → 售價 × 0.7，mutation 視為普通
澆水過 → 實際變異 = better(mutation, mutation_alt)

防連點、防重複領取

-- 扣錢：檢查和更新是同一句，看 rowcount 是否為 1
UPDATE town_players SET gold = gold - :cost
 WHERE guild_id = :g AND user_id = :u AND gold >= :cost;

-- 收成：只有一次會成功
UPDATE farm_plots SET crop_id = NULL, planted_at = NULL, ...
 WHERE guild_id = :g AND user_id = :u AND slot = :s
   AND crop_id IS NOT NULL AND ready_at <= :now;

-- 澆水：同一格同一輪只能一次
UPDATE farm_plots SET watered_by = :helper, ready_at = ready_at - (ready_at - :now) / 10
 WHERE ... AND watered_by IS NULL AND ready_at > :now;

-- 每日次數：INSERT 撞到 UNIQUE 就代表今天做過了
INSERT INTO social_actions (guild_id, actor_id, target_id, action, day) VALUES (...);

同一動作牽涉的多個寫入（扣錢、加物品、寫 ledger）放在同一個 transaction。所有金錢變動都寫一筆 ledger。

時間

DB 存 UTC Unix 秒數。「哪一天」和「哪一週」用 Asia/Taipei 計算，day 欄位存 YYYY-MM-DD。

資料表

建在現有的 data/with_you_together.db，由 town_db 啟動時 CREATE TABLE IF NOT EXISTS。不使用舊的 users 表，因為那張表沒有 guild_id。

town_players    guild_id, user_id, gold=100, plot_count=2, pickaxe_lv=1,
                last_checkin, checkin_total=0, likes=0, total_harvest=0,
                rare_found=0, created_at                PK(guild_id, user_id)

farm_plots      guild_id, user_id, slot, crop_id, planted_at, ready_at,
                mutation, mutation_alt, pest_at, pest_cleared=0,
                watered_by                              PK(guild_id, user_id, slot)
                -- crop_id 為 NULL 代表空地；slot 1..plot_count

mining          guild_id, user_id, trip_id, started_at, ready_at
                                                        PK(guild_id, user_id)
                -- 有列 = 行程進行中或待收取

inventory       guild_id, user_id, item_id, qty        PK(guild_id, user_id, item_id)
                -- 變異作物用獨立 item_id，如 tomato_gold

social_actions  id, guild_id, actor_id, target_id, action, day, created_at
                UNIQUE(guild_id, actor_id, target_id, action, day)

ledger          id, guild_id, user_id, delta, reason, created_at
                INDEX(guild_id, created_at)
                -- 本週收入榜 = SUM(delta) WHERE delta > 0 AND created_at >= 本週一
