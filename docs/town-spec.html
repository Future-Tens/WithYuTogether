第一部分 · 給玩家

怎麼玩

一天的節奏

每個伺服器各自一個小鎮，錢包和進度只在該伺服器有效。新玩家開局有 2 塊田、100 風幣。輸入 /小鎮 打開自己的農場，之後全部用按鈕操作；輸入 /小鎮 @某人 可以拜訪別人的農場。

早上簽到、收成、補種領每日風幣，收昨晚種的長時作物，換種 1–2 小時的短作物。
中午收短作物、出發挖礦賣掉收成，選一趟 4 小時的礦坑行程。
傍晚逛朋友的農場幫忙澆水、除蟲、按讚，順便賺點小費。
睡前種 8 小時作物過夜作物有足夠的寬限期，隔天早上收剛好。

設計目標是一天回來 3 次以上會玩得很順，但一天只來一次也不會被重罰。

每日簽到

每天台灣時間 00:00 換日，簽到領 50 風幣。簽到看的是累計天數，中斷不會歸零。

農田與作物

買種子、種下、等它長大、收成、賣掉。短作物時薪高但要常回來，長作物一次賺得多、適合過夜。「🌱 一鍵種植」選一種作物種滿所有空地（plantpick:all → plant:all，TownDB.plant_all 在一個交易內扣總價並種下）；風幣不夠時從小號格子種到買不起為止，沒種的格子會列在通知裡。

成熟後別放太久

寬限期 = 該作物的生長時間（最少 2 小時）。例如南瓜成熟後 8 小時內收是新鮮的，再 8 小時內收是過熟。

🥀 枯萎只能清除，無收成

🐛 蟲害

每株作物有 30% 機率長蟲，而且只會在生長期間的前 80% 出現，收成前一定有時間處理。自己或路過的朋友都可以除蟲；蟲沒除到收成時，售價 −30% 且稀有變異失效。

✨ 稀有作物

每株作物成熟時都有機會變異。變異在成熟那一刻揭曉，會直接顯示在你的公開農場畫面上。

  • 過熟才收：變異倍率保留，但售價先打 5 折。
  • 有蟲沒除：變異作廢，只剩普通價 −30%。

排行榜（伺服器內）：總資產、本週收入（每週一台灣時間 00:00 重算）、人氣、稀有收藏數、任務完成數。

農田升級：每塊田分開升級，倍數以收成當下的等級為準，多出來的份量 = 作物產量 × (倍數 − 1)，一律是普通作物；變異作物的數量跟一般田相同（例如大型田：彩虹 1 + 普通 2、巨大 2 + 普通 2）。只有升級過的田才在農場畫面顯示等級標籤。

🔔 私訊通知：首頁按鈕依序切換「🔕 關 → 🔔 每塊 → 🔔 全部」，預設關閉，每個伺服器分開設定。「每塊」是每塊田一成熟就私訊；「全部」是所有種了作物（未枯萎）的田都成熟才私訊一次，訊息列出全部成熟的田。兩種模式都會在作物過熟前 1 小時（settings.notify.overripe_warn_minutes）和礦坑挖完時私訊。同一分鐘的事件合成一則，寫明是哪個伺服器並附伺服器連結。私訊被拒（Forbidden）時自動改回「關」，玩家下次自己打開 /小鎮 時提醒一次「私訊失敗，通知已關閉，請開啟伺服器私訊」。

賣出：Select 賣單一物品、「🧺 賣出普通作物」「⛏️ 賣出普通礦物」各自一鍵賣掉該類的非稀有物品、「全部賣出」連稀有一起賣。稀有物品＝有變異的作物（金色、巨大、彩虹）＋任何礦坑中標記 rare 的礦物（金礦、寶石、秘銀、星辰石），由 svc.is_rare_item 判斷。

本頁所有數值都是初始值，會放在 JSON 裡，上線後依實際經濟狀況調整。

互動原則

  • 每個操作都 編輯同一則訊息，子畫面一律有「⬅ 返回」。
  • 錯誤、背包明細、賣出確認、訪客操作的回饋都用 ephemeral。/小鎮 @某人（成員不是自己）整個拜訪畫面都是 ephemeral；成員填自己或不填，就是公開的完整農場。
  • 按鈕用 discord.ui.DynamicItem，custom_id 格式 town:<action>:<owner_id>[:<arg>]，重啟後仍可用；guild_id 取自 interaction。
  • 每次點擊都從 DB 重讀狀態再重繪，不信任訊息上的舊資料。
  • 擁有者按鈕檢查 interaction.user.id == owner_id；訪客按鈕反過來，擁有者自己按澆水或按讚會被拒。除蟲兩邊都能按；訪客畫面的重新整理（visit）任何人都能按。
  • 倒數用 <t:ready_at:R>，Discord 會自動更新顯示。

規則實作

種下時就決定隨機結果

種植時一次擲完：mutation、mutation_alt（澆水時取兩者較好的）、pest_at（依 pest_chance 擲骰，中了就落在生長期間前 80% 內的隨機時間點，否則 NULL）。成熟前不顯示變異。這樣重新整理畫面無法刷結果。

礦坑在收取時才擲骰

收取是一次性動作，先用條件式 DELETE 搶到這趟行程，成功才擲骰發獎勵。

作物狀態判斷（純函式，放 town_service）

grace = max(2h, grow_time)
now < ready_at                      → 生長中
now < ready_at + grace              → 新鮮
now < ready_at + 2 × grace          → 過熟（售價 × 0.5）
else                                → 枯萎
pest_at = planted_at + random(0, pest_window × grow_time)   （pest_window = 0.8）
有蟲 = pest_at IS NOT NULL AND pest_at <= now AND NOT pest_cleared
收成時有蟲 → 售價 × 0.7，mutation 視為普通
澆水過 → 實際變異 = better(mutation, mutation_alt)

防連點、防重複領取

-- 扣錢：檢查和更新是同一句，看 rowcount 是否為 1
UPDATE town_players SET gold = gold - :cost
 WHERE guild_id = :g AND user_id = :u AND gold >= :cost;

-- 收成：只有一次會成功
UPDATE farm_plots SET crop_id = NULL, planted_at = NULL, ...
 WHERE guild_id = :g AND user_id = :u AND slot = :s
   AND crop_id IS NOT NULL AND ready_at <= :now;

-- 澆水：同一格同一輪只能一次
UPDATE farm_plots SET watered_by = :helper, ready_at = ready_at - (ready_at - :now) / 10
 WHERE ... AND watered_by IS NULL AND ready_at > :now;

-- 每日次數：INSERT 撞到 UNIQUE 就代表今天做過了
INSERT INTO social_actions (guild_id, actor_id, target_id, action, day) VALUES (...);

同一動作牽涉的多個寫入（扣錢、加物品、寫 ledger）放在同一個 transaction。所有金錢變動都寫一筆 ledger。

任務牆

-- 每分鐘的背景排程（也會在打開任務牆時執行）補滿每個有玩家的伺服器
for slot in 1..6:
    最新一筆 open 且已過期   → 標成 expired，立刻抽新任務
    最新一筆 open            → 不動
    最新一筆 done 且冷卻未滿 → 不動（completed_at + 30 分鐘）
    其他（沒有任務、冷卻結束）→ 抽新任務
抽任務：稀有度依權重 → 從該稀有度的模板池隨機選一個 → 每項需求擲數量
標示獎勵 = 進位到 10( Σ 需求市價 × 數量 × reward_mult )，萬用需求以最便宜的作物計價（＝最低值）
實際獎勵 = max(標示獎勵, 進位到 10( Σ 實際交出物品市價 × reward_mult ))，完成時寫回 reward 欄位

-- 交付：BEGIN IMMEDIATE 內檢查 status='open' 且未過期 → 扣物品 → 標 done → 發風幣 → 檢查成就
-- 兩人同時按只有一個交易成功，另一個看到「手慢了」，物品不會被扣

私訊通知

-- notify_loop：每分鐘一次，一個 BEGIN IMMEDIATE 交易內算出並標記，交易結束後才發私訊
for 每個 notify != 'off' 的玩家:
    每塊有種東西的田（notified 位元：1 = 已通知成熟、2 = 已提醒過熟）
        枯萎          → 位元全設，不通知
        新鮮/過熟且無 1 → 成熟候選
        新鮮且 now ≥ 過熟時間 − 60 分鐘且無 2 → 快過熟提醒；已過熟 → 直接設 2 不提醒
    mode = 'all' → 所有未枯萎的田都已成熟且有成熟候選時，通知全部成熟的田；否則不通知成熟
    礦坑 now ≥ ready_at 且 notified = 0 → 通知並設 1
種下新作物 / 收成清空 → notified 歸零；新行程 INSERT → notified 預設 0
切換通知模式時 → 把目前已成熟／挖完的先標成已通知（玩家正看著畫面）
私訊 Forbidden → notify = 'off'、notify_failed = 1；/小鎮 打開自己農場時讀取並清除 notify_failed

每塊田只會通知一次；機器人停機期間成熟的東西，重啟後下一分鐘補發一次。私訊發送失敗（非 Forbidden）不重試，避免重複。

時間

DB 存 UTC Unix 秒數。「哪一天」和「哪一週」用 Asia/Taipei 計算，day 欄位存 YYYY-MM-DD。

資料表

建在現有的 data/with_you_together.db，由 town_db 啟動時 CREATE TABLE IF NOT EXISTS。不使用舊的 users 表，因為那張表沒有 guild_id。

town_players    guild_id, user_id, gold=100, plot_count=2, pickaxe_lv=1,
                last_checkin, checkin_total=0, likes=0, total_harvest=0,
                rare_found=0, created_at, title,
                notify='off'(off/each/all), notify_failed=0
                                                        PK(guild_id, user_id)

farm_plots      guild_id, user_id, slot, tier=1, crop_id, planted_at, ready_at,
                mutation, mutation_alt, pest_at, pest_cleared=0,
                watered_by, notified=0                  PK(guild_id, user_id, slot)
                -- crop_id 為 NULL 代表空地；slot 1..plot_count

mining          guild_id, user_id, trip_id, started_at, ready_at, notified=0
                                                        PK(guild_id, user_id)
                -- 有列 = 行程進行中或待收取

inventory       guild_id, user_id, item_id, qty        PK(guild_id, user_id, item_id)
                -- 變異作物用獨立 item_id，如 tomato_gold

social_actions  id, guild_id, actor_id, target_id, action, day, created_at
                UNIQUE(guild_id, actor_id, target_id, action, day)

ledger          id, guild_id, user_id, delta, reason, created_at
                INDEX(guild_id, created_at)
                -- 本週收入榜 = SUM(delta) WHERE delta > 0 AND created_at >= 本週一

town_quests     id, guild_id, slot, rarity, requirements(JSON), reward,
                created_at, expires_at, status(open/done/expired),
                completed_by, completed_at          INDEX(guild_id, slot, id)
                -- 每格保留歷史，MAX(id) 是目前的任務；任務榜 = COUNT(*) WHERE status='done'

town_achievements  guild_id, user_id, achievement_id, earned_at
                                                        PK(guild_id, user_id, achievement_id)
                -- town_players.title 存裝備中的 achievement_id（舊表以 ALTER TABLE 補欄位）

town_stats      guild_id, user_id, key, value          PK(guild_id, user_id, key)
                -- 無法從其他表推算的累計數字：mine_trips、chests、crop_gold、crop_rainbow、ore_<id>
                -- 其餘成就統計直接算：簽到/收成/讚數取 town_players，澆水/按讚次數取 town_social，
                -- 除蟲次數與賣出總額取 town_ledger，任務數取 town_quests（舊存檔也算得到）

guild_settings.announce_channel   -- /設定公告；由 DatabaseManager 管理，全機器人共用

檔案分工

檔案負責
cogs/town_cog.py/小鎮 指令、所有 View 與 DynamicItem、embed 繪製
utils/town_service.py遊戲規則：擲骰、狀態判斷、計價。不碰 Discord、不碰 DB，可直接寫單元測試
utils/town_db.py建表與所有 SQL，沿用 DatabaseManager.get_connection()
data/town/*.json作物、變異、礦坑、礦物、升級與獎勵數值，任務池（quests）與成就（achievements）
cogs/settings_cog.py/設定公告 指令
utils/announce.pysend_announcement()：發到公告頻道，沒設定時改發 fallback 頻道或不發

目前 sqlite3 是同步呼叫，玩家量小沒問題；之後若有延遲再換 aiosqlite。
